Decisions locked

Data, not vibes.

Four findings now become design rules for the build.

D1 / LINEUP

Super goes first

Nano's 80% threat recall means one in five threats slipped through. It cannot be the front door yet. Nano may re-audition on the larger real-email benchmark.

D2 / FAILURE MODE

Never fail open

Two Nano responses could not be parsed. In the real pipeline, malformed output triggers retry and escalation—it can never silently become “safe.”

D3 / TAXONOMY

Separate threat from type

Both models sometimes confused BEC with phishing while still recognizing danger. The verdict schema should distinguish “is it malicious?” from “which class?”

D4 / EMAIL TRUST

Check five trust signals

SPF checks approved senders, DKIM checks the message signature, and DMARC checks alignment and policy. BIMI adds brand-mark evidence; MTA-STS shows whether the domain publishes a secure inbound-mail policy. Each becomes evidence—not a verdict by itself.

BENCHMARK NOTE

Twenty synthetic emails are a compass, not a map. Phase 4 will retest on real, anonymized mail with label-leak fixes, injection tests, and reproducible scripts.

Architecture agreed

Evidence before opinion.

A hosted Python pipeline replaces the local workflow so judges can test a real public product.

01 / INPUT

Forward email

Zero-install entry point for a judge or user.

02 / EXTRACT

Parse facts

Sender, headers, links, message text, requested action.

03 / EVIDENCE

Check receipts

Planned checks: SPF, DKIM and DMARC results; BIMI DNS/logo or VMC evidence; MTA-STS DNS declaration and published policy; plus lookalikes, RDAP age, Tavily intel and sender history.

04 / CLASSIFY

Ask Super

Nemotron must reason from—and cite—the gathered evidence.

05 / VALIDATE

Return report

Schema check, fail-safe retry, verdict page and reply.
